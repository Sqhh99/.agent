# C++ 测试规范

小徐的 C++ 项目对测试的要求。写完功能模块/控件后，测试必须跟上；不为了「有测试」而写测试。

## 硬规则

- **先写代码，再写测试**。代码完成度是第一位的，测试用来验证与守卫，不是先行的形式。
- 功能模块或控件完成 = 必须配套**单元测试 + 集成测试**，覆盖功能完整性。
- 测试程序的原则是**最大化场景覆盖**——把真实会用到的路径、边界、组合都跑到。
- **禁止为凑工作量写测试**：不会发生的错误不写测试；没有场景价值的测试不如不写。

## 怎么判断一条测试值不值得写

- 它验证的路径真实可触发？→ 写
- 它只是演示「程序不可能出错」？→ 删
- 它能拦住将来回归？→ 写
- 它只是为了测试数量好看？→ 删

## 验收

- [ ] 每个功能模块/控件有单测 + 集成测试
- [ ] 测试清单与场景清单一一对应，无凑数项
