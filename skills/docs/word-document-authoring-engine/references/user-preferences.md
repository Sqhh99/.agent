# 用户 Word 文档偏好画像

## 1. 核心取向

用户的目标通常不是获取一篇泛化文章，而是获得可用于项目论证、内部汇报、技术评审、方案设计或后续招采的正式工程文档。评价重点是：内容能否真正回答问题、方案是否完整、设备与算法是否落地、图片是否清楚、文档能否直接使用。

## 2. 稳定偏好

### 内容

- 需求和现有问题必须先出现；
- 必须说明传统解决方法及其不足；
- 提出的方案要对应痛点，不能只列设备；
- 需要说明具体设备、传感器、载荷、软件平台和数据链；
- 技术主题应加入算法原理、公式、指标和验证方法；
- 当资料不足时主动联网研究补充；
- 项目建议书应有建设路线、验收指标、风险控制和效益；
- 不要根据常识自行添加图片或需求中未体现的功能；
- 需要区分事实、建议值和待验证项。

### 图表

- 配图有必要，但不宜装饰化；
- 图题在图下方，图片内部不放主标题；
- 图中文字、箭头和框体不能重叠；
- 常用黑白、黑灰或克制深蓝；
- 表格不宜过多，普通无彩色装饰；
- 更偏好架构图、流程图、部署图和技术路线图。

### 交付

- 直接输出可编辑 DOCX；
- 文件名正式、简洁；
- 不附带无关过程文件；
- 对既有文档的增补应整合进原结构，而不是简单追加；
- 生成后应循环检查排版和图片质量。

## 3. 适配原则

这些偏好是默认值，不应覆盖用户在具体任务中的明确要求。若用户提供模板、字号、颜色、目录或篇幅要求，以当前任务为准。
