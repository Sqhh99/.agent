# C++ 设计原则与注释规范

小徐的 C++ 代码在「怎么设计」和「怎么写注释」上的统一标准。

## 设计原则（核心七条）

代码设计必须遵守经典设计原则：

1. **单一职责** — 一个类/函数只做一件事
2. **开闭原则** — 对扩展开放，对修改关闭
3. **依赖倒置** — 依赖抽象，不依赖具体实现
4. **接口隔离** — 接口按调用方拆分，不强迫依赖不需要的接口
5. **里氏替换** — 子类必须能替换父类而不破坏行为
6. **迪米特法则** — 最少知识：不和自己无关的对象直接通信
7. **组合/聚合复用** — 优先组合/聚合，少用继承复用

## 注释规范

- **`.h` 头文件**：类、方法、变量都要写注释，使用 **Doxygen 风格**（`///`、`/** */`、`@param/@return`）。
- **`.cpp` 源文件**：不写注释（逻辑靠代码自解释，头文件注释已说明契约）。

## 验收

- [ ] 公开 API 的 `.h` 有完整 Doxygen 注释（类/方法/变量）
- [ ] `.cpp` 无冗余注释
- [ ] 新类能指出它满足哪几条设计原则
